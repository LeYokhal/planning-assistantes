## 3. Écarts au plan relevés en Phase 3 (seize, tous acceptés)

Les plus structurants :
1. **`audit/models.py` touché d'une ligne** — la liste d'interdits du prompt le nommait, le plan (C-5, § 2) demandait la
   constante dans le `TextChoices` qui y vit. Incohérence de ma rédaction ; le plan a primé, aucune migration.
2. **Écart 3, tranché par Yohan** : le type d'absence s'affiche dans sa propre fiche du jour (« Congé payé — Validée »),
   les deux tests de confidentialité sont adaptés → **D6b.11 amendée**.
3. **`jours_publies` rend une troisième clé** `sans_compte_rendu` (liste des jours dont la version source n'a pas de
   compte-rendu) : la raison « Effectif non renseigné pour ce mois » d'un jour voisin n'était pas calculable avec deux clés.
4. `fiche.absences[]` porte une clé `ecole` en plus de `type`, `statut`, `bloquant`.
5. Dates conservées au format des tests existants (`29/09/2026` dans la fiche, « Du 26/05/2026 au 30/05/2026 » dans les
   absences) plutôt qu'aux formats du plan, pour ne pas retoucher d'assertions.
6. `<optgroup>` sans balise de fin (implicite en HTML) ; groupe vide non rendu, par `ifchanged`.
7. Suffixe « imports differents de la publication » émis aussi quand `verifications == []` — conséquence de la comparaison
   de paires, visible en fabrique de test seulement.
8. Un test corrigé après un faux rouge : `"<details"` → `'<details class="mois"'` (la barre porte `<details class="avatar">`).

Les huit autres (imports relatifs, tuple `AUTRES` au lieu de `NOMS`, titre de `nouvelle.html`, ordre d'écriture des
gabarits au lot 3, typage défensif dans `effectif.calculer`, bloc `titre_page` redéfini, etc.) sont sans conséquence sur le
contrat ; le détail est dans le rapport de checkpoint.

## 6. Leçons

- La revue technique contre le code a rattrapé **neuf erreurs factuelles** du diff plan v1, dont une qui changeait un
  résultat métier (les praticiens à jours fixes, absents de `data["jours"]`). Le coût — une passe de lecture seule — est
  très inférieur à celui d'un diff à refaire.
- Ma propre revue de Phase 1 avait affirmé à tort qu'un test ne posait pas d'absence pour la salariée du jeu fictif ; c'est la Phase 3 qui l'a
  découvert. Un fait « vérifié » dans un rapport reste à re-vérifier quand il devient bloquant.
- Prompt et plan doivent dire la même chose : l'interdit sur `audit/models.py` contredisait le plan et a coûté un écart
  à justifier. Le plan est le contrat ; le prompt ne doit que le servir.
- La frontière manuelle sur la base de production a tenu et n'a rien coûté : trois minutes, une fois le shell trouvé.
  Ce qui a coûté du temps, c'est de chercher ce shell — mes prompts envoyaient vers la CLI locale (jeton expiré, mauvais
  dossier) alors que l'interface web du service ouvre un terminal directement dans le conteneur, au bon endroit.
  **À retenir pour toute commande en production : passer par le shell du service Railway.**
